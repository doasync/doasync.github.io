# Тест: Видимая история в контексте

## Что было изменено:

1. **Frontend (main.js)**:
   - При обычной отправке сообщения для постоянных чатов теперь собирается история из видимых элементов UI
   - История собирается из всех `.message-container`, исключая:
     - `.stop-notification-message` (уведомления об остановке)
     - `.error-message` (сообщения об ошибках)
     - `.loading-indicator-container` (индикаторы загрузки)
     - `.editing` (сообщения в процессе редактирования)

2. **Backend (chat_service.py)**:
   - Теперь сначала проверяется наличие переданной истории из request
   - Загрузка из БД происходит только как fallback, если история не передана

## Как тестировать:

1. Откройте чат и отправьте несколько сообщений
2. Регенерируйте одно из сообщений ассистента
3. Проверьте в консоли браузера (F12), что отправляется правильная история:
   ```javascript
   console.log("sendMessageInternal: Собрана видимая история из UI для постоянного чата: X сообщений")
   ```
4. Проверьте в логах сервера:
   ```
   Chat Service (Non-Streaming): Используется переданная история: X сообщений
   ```
   или для стриминга:
   ```
   Chat Service (Prepare Stream): Используется переданная история: X сообщений
   ```

## Что это решает:

- При регенерации сообщения старые версии не будут включаться в контекст
- При редактировании сообщения только видимая версия будет в контексте
- При остановке генерации незавершенные ответы не попадут в контекст
- Контекст всегда соответствует тому, что видит пользователь в UI
